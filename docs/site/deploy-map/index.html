§3秘密・環境変数の置き場所

vars に秘密を載せない。SESSION_SECRET は両 Worker で同一値（32 バイト以上）。 NEXT_PUBLIC_* はビルド時に埋め込まれるため、ドメイン変更時は再ビルド必須。

名前 app api 設定方法 備考
SESSION_SECRET secret secret wrangler secret put 両側同一。既知漏洩値はコードで拒否
GOOGLE_CLIENT_ID secret — wrangler secret put 本番ログイン用（未設定でも UI は起動可）
GOOGLE_CLIENT_SECRET secret — wrangler secret put 同上
NEXT_PUBLIC_SITE_URL build env — build 前の env / GH vars OAuth redirect・招待 URL のベース。production で必須
API_WORKER_URL 禁止 — — 本番は binding。設定すると HTTP 優先で事故
NEXT_PUBLIC_API_WORKER_URL 禁止 — — 本番は同一オリジン WS

§4初回・手動デプロイ順

順は固定: api → app（service binding 先が先に存在する）。 スクリプトは npm run deploy（api → app）/ deploy:api / deploy:app。

STEP 1
D1 作成
wrangler d1 create idea-flow-lobby
→ database_id を wrangler に反映
STEP 2
Remote migrate
wrangler d1 migrations apply DB --remote --config workers/wrangler.jsonc
STEP 3
api secret + deploy
secret put SESSION_SECRET
npm run deploy:api
STEP 4
app secret + build
secret put（SESSION / Google）
NEXT_PUBLIC_SITE_URL=…
STEP 5
app deploy
npm run deploy:app
= build:cf && wrangler deploy
Durable Objects は Workers Paid が実質前提 Free プランでは RoomDO を本番運用できない。ハッカソン規模でも課金確認が必要。

§5継続デプロイ（release）

feature/* → develop（開発）/ develop → release（本番トリガ）。 release への push または merge で deploy.yml が自動実行される。 PR は ci.yml のみ。Worker 本番デプロイは deploy.yml（push to release）。 手動デプロイは npm run deploy = D1 remote migrate → api → app（CI と同じ順）。

Worker の SESSION_SECRET / Google は Actions から毎回 put しない 初回手動（または Dashboard）で維持。ローテ時だけ人手で両 Worker を同時更新。

§6カスタムドメイン（本番必須）

同一オリジンのため app にだけ ドメインを付ける。api は service binding で閉じるので公開 URL 不要。 本番リリースには必須の設定。

作業内容
DNS ドメインを Cloudflare に接続（NS 切替 or Registrar）
Worker ルート wrangler deploy -c wrangler.jsonc --domains ideaboost.dev
OAuth https://ideaboost.dev/auth/callback を Google Console に追加
SITE_URL NEXT_PUBLIC_SITE_URL を新 URL にして再ビルド + 再デプロイ
